# 💻 OS Command Injection

## 📌 Overview

OS Command Injection occurs when an application passes user-controlled input to an operating system command without proper validation or sanitization.

In this lab, DVWA was configured with the **Low** security level to demonstrate command injection using the Ping functionality.

---

## 🎯 Target

* **Application:** Damn Vulnerable Web Application (DVWA)
* **Vulnerability:** OS Command Injection
* **Security Level:** Low
* **Environment:** Local Windows XAMPP Lab
* **Target URL:** `http://127.0.0.1/DVWA/`

---

## 🎯 Objective

The objective was to determine whether additional operating system commands could be executed by injecting command separators into the application's input.

---

## 🧪 Step 1: Baseline Test

The following normal input was submitted:

```text id="h0j4w7"
127.0.0.1
```

The application executed the ping command successfully and returned four replies from the local system.

---

## 🧪 Step 2: Command Injection

The following payload was submitted:

```text id="q3w8pe"
127.0.0.1 && whoami
```

The `&&` operator was used to execute the second command after the ping command completed successfully.

The application returned the Windows user context:

```text id="x8v2km"
desktop-unn7ilo\yogesh
```

This confirmed that an additional operating system command was executed through the application's input.

## 🕵️ Step 3: Burp Suite Evidence

Burp Suite was used to inspect the HTTP request generated by the application.

The injected command was visible in the request parameter:

```text id="n5t9rx"
127.0.0.1 && whoami
```

## ✅ Vulnerability Confirmation

The vulnerability was confirmed because:

1. The application accepted user-controlled input as a host value.
2. A command separator was accepted by the application.
3. The additional `whoami` command was executed.
4. The server returned the Windows user context.

---

## ⚠️ Impact

OS Command Injection can allow an attacker to execute operating system commands with the privileges of the affected application.

Potential impact can include:

* Unauthorized system information disclosure
* Execution of unauthorized commands
* Access to files available to the application
* Modification or deletion of accessible data
* Further compromise depending on the application's privileges

---

## 🛡️ Remediation

Recommended defenses include:

* Avoid passing user input directly to operating system commands.
* Use safe APIs instead of shell execution where possible.
* Apply strict allowlist-based input validation.
* Validate that submitted host/IP values match the expected format.
* Avoid shell interpretation of user-controlled input.
* Run the application with the minimum privileges required.

---

## 📌 Conclusion

The DVWA OS Command Injection vulnerability was successfully demonstrated.

A normal ping request was first executed successfully. A modified input containing a command separator and the `whoami` command then caused an additional operating system command to execute, confirming the vulnerability at the configured Low security level.
