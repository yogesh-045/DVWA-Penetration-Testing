# 🕸️ Reflected Cross-Site Scripting (XSS)

## 📌 Overview

Reflected Cross-Site Scripting (XSS) occurs when user-controlled input is reflected back into a web page without proper output encoding or sanitization.

In this lab, DVWA was configured with the **Low** security level to demonstrate a basic reflected XSS vulnerability.

---

## 🎯 Target

* **Application:** Damn Vulnerable Web Application (DVWA)
* **Vulnerability:** Reflected Cross-Site Scripting (XSS)
* **Security Level:** Low
* **Environment:** Local Windows XAMPP Lab
* **Target URL:** `http://127.0.0.1/DVWA/`

---

## 🎯 Objective

The objective was to determine whether user-controlled input could be injected into the page and executed as JavaScript.

---

## 🧪 Step 1: Baseline Test

A normal input was first submitted:

```text id="g7q1p0"
test
```

The application reflected the input back to the page:

```text id="0rj1qu"
Hello test
```

This confirmed that the supplied input was being reflected in the response.

## 🧪 Step 2: XSS Payload

The following proof-of-concept payload was submitted:

```text id="a6s7cw"
<img src=x onerror=alert(1)>
```

The payload triggered a JavaScript alert displaying:

```text id="2z5k1v"
1
```

This demonstrated that the injected JavaScript event handler was executed by the browser.

## 🕵️ Step 3: Burp Suite Evidence

Burp Suite was used to inspect the HTTP request generated by the application.

The reflected XSS payload was visible in the request parameter:

```text id="4n6p8r"
name=<img src=x onerror=alert(1)>
```

## ✅ Vulnerability Confirmation

The vulnerability was confirmed because:

1. User-controlled input was reflected by the application.
2. HTML markup supplied through the input was interpreted by the browser.
3. The `onerror` event handler executed JavaScript.
4. A browser alert displaying `1` was successfully triggered.

---

## ⚠️ Impact

A reflected XSS vulnerability can potentially allow an attacker to execute arbitrary client-side JavaScript in a victim's browser when the victim interacts with a maliciously crafted URL or request.

Depending on the application's security controls and browser context, XSS may be used for:

* Phishing and page manipulation
* Session-related attacks
* Unauthorized actions performed in the victim's browser
* Capturing sensitive information accessible to client-side scripts

---

## 🛡️ Remediation

Recommended defenses include:

* Properly encode untrusted output before inserting it into HTML.
* Validate and sanitize user input where appropriate.
* Use context-aware output encoding.
* Implement a restrictive Content Security Policy (CSP).
* Use secure cookie attributes such as `HttpOnly` and `SameSite` where applicable.
* Avoid directly inserting untrusted input into HTML or JavaScript contexts.

---

## 📌 Conclusion

The DVWA Reflected XSS vulnerability was successfully demonstrated in the local lab.

A crafted HTML payload was reflected by the application and its JavaScript event handler executed successfully, confirming the presence of a reflected XSS vulnerability at the configured Low security level.
